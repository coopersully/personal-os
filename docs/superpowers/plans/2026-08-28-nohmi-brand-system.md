# nohmi Brand System Implementation Plan

> **Required sub-skill:** Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to execute this plan task-by-task.

**Goal:** Rename the public product to **nohmi** and ship a cohesive, enforceable, flat shadcn design system across the web app, PWA, desktop shell, API/MCP copy, and current product documentation.

**Architecture:** Keep `personal-os` as the stable internal identifier for packages, environment variables, database/runtime names, compatibility headers, and the Tauri bundle identifier. Put public brand values in a tiny web brand module, express visual decisions through semantic CSS variables, and make the local shadcn registry the only component primitive layer. Product pages compose shadcn components; they do not introduce a second UI kit or raw visual values.

**Tech stack:** React 19, TypeScript, Vite, Tailwind CSS v4, shadcn `radix-nova`, Radix UI, Lucide, Geist, Vitest/Testing Library, Playwright, Tauri 2, Biome, pnpm.

**Spec:** [`docs/superpowers/specs/2026-08-28-nohmi-brand-system-design.md`](../specs/2026-08-28-nohmi-brand-system-design.md)

## Global constraints

- Public spelling is lowercase `nohmi`; pronunciation is “know me”; the verbal promise is “know what matters.”
- Preserve stable internal identifiers: `personal-os`, `@personal-os/*`, `PERSONAL_OS_*`, database and runtime names, `x-ilo-client`, existing deployed `*.ilo.coopersully.me` URLs, and `app.personal-os.desktop`. Renaming compatibility identifiers requires a separate migration.
- Preserve domain boundaries. This work changes presentation and public copy only; it does not change domain models, persistence, API routes, auth scopes, or connector behavior.
- Resting UI uses flat fills and whitespace. Do not add decorative borders, box/drop shadows, gradients, translucency, backdrop blur, or glass. Borders remain only where they encode real structure, such as calendar/table grids, separators, focus, invalid state, and selection geometry.
- nohmi owns no accent color. Product chrome, primary actions, active navigation, selection, and focus are grayscale. Color comes only from user/provider material or conventional semantic state, and no available hue receives more saturation, area, or hierarchy than another.
- Use the local shadcn registry under `apps/web/src/components/ui`. Do not recreate Button, Badge, Input, Label, Card, Empty, or Spinner in a package or page stylesheet.
- Keep all interaction states accessible: visible focus, keyboard navigation, reduced motion, text contrast at WCAG 2.2 AA or better, and non-color state cues.
- Use Lucide for product icons. The `n` tile and lowercase wordmark are brand assets, not a second icon family.
- Do not commit `.superpowers/`; it contains the temporary visual companion used during design exploration.
- Every task follows red → green → focused verification → commit. Do not broaden a task when its named checks pass.
