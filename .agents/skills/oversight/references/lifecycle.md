# Implementation lifecycle

Use the existing outcome record and [handoff contract](../../../../docs/engineering/agent-handoffs.md).
Keep actual stage separate from waiting/blocked conditions. Enter at the next missing obligation;
no mandatory restart when changing helpers, resuming a chat or receiving a status question.

| Evidence | Next action within recorded authority |
| --- | --- |
| Equivalent work already active | Observe the existing owner; do not duplicate instructions or writers |
| Scope or prerequisite contract unresolved | Research or obtain the specific decision while independent work proceeds |
| Stable prerequisite available | Assess affected consumers; integrate/catch up when the next gate needs it |
| Actionable review feedback | Route one evidence-backed repair to the existing implementation owner |
| Implementation complete, required evidence missing | Request the named check or independent repository `deep-review` |
| Requested draft not published | Use repository `create-pr`; record pending final gates honestly |
| Reviewed candidate frozen | One verification owner obtains complete local or equivalent hosted evidence |
| Current candidate reviewed and verified | Refresh live authority, eligibility, reviews, threads and protected merge gates |
| Merged but acceptance remains | Verify the explicit release/observation criteria; merging alone is insufficient |
| Full outcome accepted | Report receipts and remaining unrelated work; cleanup only within its separate grant |

Before dispatch, inspect the executor's current work and last instruction. Use one bounded handoff
per owner, with checkout/branch/PR, applicable workflow, acceptance and permitted effects. Chain
already-authorized dependent steps with exact continuation predicates, source restrictions, resource
owner, retry bounds and stop conditions. After interruption resume only unfinished applicable steps;
unchanged grants require no repeated acknowledgement. Changed scope, uncertain ownership, new failure
class or product/security decision returns to Lead. A current ownership transfer supersedes old grants.

Distinguish branch ancestry, stable source contracts, merge safety, release order and observation.
Reviewed stable source can satisfy a source-inclusion prerequisite on an authorized integration base;
only a specifically required merged prerequisite must be merged and present. Published-migration
immutability and actual repository freshness gates still apply. Base advancement alone does not
justify chasing every parent commit. Assess affected contracts and batch ordinary drift at integration
boundaries. Never change a checkout while its owner is testing it.

For genuine multi-owner outcomes, assign one shared-path/composition worker and consumer verification
owners. Use a rolling integration branch only when needed for cross-slice acceptance. Single-owner
work stays on its existing branch. For shared contracts, authorization, locking, migrations, UI modes
and audit/idempotency, name transitive consumers and existing fixtures early. Run their setup/teardown
and negative/failure paths, not just new happy-path tests. Review checks for omissions.

Record dispatch target, action, packet revision, head/base, feedback content, delivery receipt and
observed outcome. Counts alone miss edited questions. Retain actionable findings even if their thread
is resolved. Classify nearby consumers as affected, covered, not applicable or unknown; unknowns block
only the affected readiness claim. Prefer one shared-owner repair plus consumer checks over duplicate
fixes. Cross-owner messaging still needs its own scope.

A blocker retains cause, affected gate, first observation, latest evidence, responsible owner, prior
attempts and next recovery condition. Retry only when evidence changes the recovery path; elapsed
time is not recovery. A tool failure is not a code failure: inspect partial effects before resending.
Apply the handoff contract's no-progress limit and delivery verification's transient retry bound.
Keep unassessed concerns with owner, age and next trigger; advance immediate handoff blockers first,
then oldest unassessed concerns, grouped by consumer. Silence never erases unfinished work.
