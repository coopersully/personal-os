# Monitoring and recovery

Monitoring is opt-in. Verify actual scheduler context, not quoted wake text. Before a scheduled pass,
verify saved automation identity, owning chat, outcome, instructions/baseline, active state, scope,
authority, cadence/timezone and notification intent. A delayed wake cannot resume paused work.
Read back authorized configuration changes; configured is not evidence of an executed scheduled pass.
Missing routing blocks dependent dispatch, not useful read-only diagnosis. Do not create a monitor
as a fallback without scheduling authority.

## Incremental checks

Every oversight heartbeat first performs the oversight skill's
[tracking and presentation check](../SKILL.md#every-oversight-heartbeat-tracking-and-presentation),
even if all work sources are unchanged. Read live section name/membership/order and dedicated titles;
repair authorized drift and read back into the existing setup record. Unavailable reads or uncertain
writes remain gaps, never successful unchanged checks. This mandatory per-wake check is separate
from the broader periodic reconciliation below and creates no scheduler or Linear status spam.

Check every in-scope owner, including no-PR owners and executor errors. Prefer compact status cursors;
compare returned identities with requested targets and fetch missing owners separately. Read changed
turns or named evidence gaps. Check unchanged PR heads for edited feedback, replies, deletions and
resolution changes. Complete relevant pagination; counts, head SHAs and first pages do not establish
source coverage. A failed/partial read is unknown, not unchanged.

Inspect saved triggers each pass even if sources did not change. Recheck owner activity before
sending; deduplicate against the last instruction, delivery receipt and observed result. Bundle
straightforward authorized dependent steps with explicit stop conditions rather than waiting for a
new wake for each routine step. Preserve productive active work.

Full reconciliation discovers new/missing owners and checks acceptance, coverage, sidebar and monitor
state. Perform it at initialization, explicit reset/full refresh, unreliable baseline and the recorded
risk-based reconciliation deadline. This deadline does not change wake cadence. Refresh required
live evidence before consequential actions regardless of the deadline.

Track checked-at separately from last-assessed revision/time. Successfully observing blocked work is
source coverage, not acceptance. Preserve successful checkpoints and retry missing sources without
repeating unrelated assessments. Cache successful empty discovery only until its recorded trigger.

## Continuity and reset

Keep scope, decisions/rationale, authority, pauses, deadlines, owner graph, acceptance gaps, blocker
age, pending actions and next triggers in the existing compact registry/checkpoint. Link detailed
receipts instead of rereading history every wake. Use the existing single-writer/claim protocol and
compare expected revisions under the claim before updating file-backed shared state. Atomic file
replacement alone does not prevent lost updates. Missing concurrency support blocks competing writes;
do not invent another registry or claim a locking helper exists.

Reset rebuilds derived state from live sources while preserving decisions, scope, grants, pauses,
artifacts, dispatch history and unfinished obligations. If a source is unavailable, report partial
reset and retain the last verified baseline. Repair only reversible setup drift with proven identity
and intended configuration within authority. Never guess recipients, model, schema, cadence or scope,
restart paused work, or infer stopped ownership from an expired heartbeat. Follow the handoff contract
before replacing an executor and preserve unpushed work.

## Reporting and continuation

The personal procedure is quiet on unchanged passes. nohmi retains its explicit scheduled-report
preference: each scheduled oversight wake ends with a short visible report, including unchanged
state and its next trigger. Preserve an explicit user quiet/mute override and the saved notification
policy; do not silently change existing monitors. Internal polling and manual callbacks need no
repeated narration. Update checked-at metadata rather than appending duplicate private narratives.

Before yielding, identify a verified active monitor, a bounded wait or user-driven follow-up as the
next trigger. A checkpoint, dispatch receipt or active child does not guarantee a future parent wake.
No background work or monitoring is claimed without the corresponding live evidence.
