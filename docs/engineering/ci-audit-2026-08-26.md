# CI Audit — 2026-08-26

pnpm workspace graph, Vitest and Playwright suites, Drizzle migrations, Docker

## Executive assessment

The current CI has a strong broad gate: formatting, repository contracts,
TypeScript, high-threshold coverage, builds, browser acceptance, Terraform
format/validation, and two-platform Tauri compilation. Its primary weakness is
not missing generic JavaScript tests; it is that almost all of this work runs for
almost every change, while several production-specific surfaces are validated
only indirectly or during deployment.

The recommended target is an always-triggered CI workflow with:

1. a small, tested, fail-closed change-classification job;
2. conditional validation jobs selected from that classification;
3. one stable aggregate `CI required` job for branch protection; and
4. a full, non-selective safety-net run on every push to `main`.

This preserves coverage and makes pull-request feedback proportional. It avoids
workflow-level `paths` filters because GitHub documents that a skipped required
workflow can remain pending, and because native path filtering evaluates only a
bounded changed-file list. Job-level skips report success and can be safely
aggregated.

## Observed performance

A representative successful pull request run on 2026-08-25 used approximately
23.3 runner-minutes across five parallel jobs and had an 11 minute 22 second
critical path:

| Job | Elapsed | Main cost in the sample |
| --- | ---: | --- |
| Quality and browser acceptance | 11:22 | `pnpm check` 8:38; Playwright 1:58 |
| Desktop — Windows | 5:35 | runner/tool setup, then native compile 3:03 |
| Lint and format | 2:58 | `pnpm lint` 2:31 |
| Desktop — macOS | 2:46 | native compile 1:45 |
| Terraform | 0:35 | provider initialization |

The quality job runs `pnpm check`, and `pnpm check` itself runs `pnpm lint`.
Therefore lint is installed and executed in two Linux jobs. Both desktop jobs
also install the entire workspace and rebuild the web app. There is no CI
workflow concurrency group, so repeated pushes keep obsolete runs alive. Recent
failed PR runs commonly failed only at `pnpm check` after the other independent
jobs had already consumed runner time.

The main branch repeats the full CI after the pull-request run, which is correct
as a merge-commit safety net and is also the current prerequisite for production
deployment. The optimization should therefore be strongest on pull requests,
while retaining full validation on `main`.

## Current validation map

| Surface | Current validation | Material gap |
| --- | --- | --- |
| Terraform | `fmt`, backendless init, `validate` for two roots | No TFLint, IaC security scan, native Terraform tests, lockfile read-only enforcement in CI, or real-state speculative plan |
| TypeScript/React/API/MCP | Biome, contracts, typecheck, global Vitest coverage, builds | Every code change runs the whole graph; coverage is global rather than independently enforced per ownership boundary |
| Browser | Desktop/mobile Chromium Playwright | Runs for MCP-only, Terraform-only, desktop-shell-only, and documentation changes |
| Tauri/Rust | Debug compile on macOS and Windows | No `cargo fmt`, Clippy, or `cargo test`; stable toolchain floats |
| Database | Migrations are replayed by integration/E2E tests; Drizzle schema exists | `drizzle-kit check` is not a named CI gate; migration/schema changes cannot be selected independently |
| Containers | Built and scanned during production deployment | A broken Docker build can pass CI and fail only after deployment starts |
| Workflows/scripts | Biome plus several custom Node contract checks | No explicit actionlint/ShellCheck/Python syntax lane for all production workflow helpers; action references use movable tags |
| Dependencies | Dependabot plus `pnpm audit --prod` on every quality run | Network-dependent audit runs on unrelated PRs; no PR dependency-diff gate |
| Production | Deployment health checks and an hourly health workflow | Successful `main` CI can start deployment even when the merge is not deployable; workflow permissions are broader than each job requires |

## Findings and recommendations

### P0 — Preserve correctness while introducing selective CI

Add a repository-owned classifier rather than embedding a growing set of YAML
globs in job expressions. It must calculate the pull-request merge-base with a
full checkout, classify every changed path, include transitive workspace
dependents, and return `full=true` for an unknown path, an empty/failed diff, a
workflow/classifier change, or a root toolchain/lockfile change. Unit tests must
cover every owned top-level path and the fail-closed cases.

Keep CI triggered for all pull requests. Use job-level `if` expressions, then an
aggregate required job with `needs` that rejects `failure` or `cancelled`, accepts
`success` or intentional `skipped`, and prints the selected scopes. Keep a full
run on `main` regardless of the classifier. Do not make Playwright's
`--only-changed` heuristic the only browser gate; Playwright explicitly says it
can miss tests and recommends a later full run.

Recommended initial scopes:

| Changed surface | Required PR lanes |
| --- | --- |
| Docs/Markdown only | classifier and aggregate required check only; add a docs-specific lane later if Markdown/link policy is adopted |
| `infra/**` | Terraform static; speculative plan when trusted credentials are available |
| `.github/**`, root manifests/config, CI classifier | full CI plus workflow/script validation |
| `packages/domain` | all transitive TypeScript dependents, coverage, builds, browser, desktop, containers |
| `packages/database` or migrations | database + API dependents, migration replay/check, browser, API container |
| `packages/connectors` | connectors + API dependents, coverage, browser, API container |
| `packages/api-client` | client + web/MCP dependents, coverage, browser, MCP container, desktop |
| `packages/ui` or `apps/web` | web dependents, coverage, browser, web build, desktop |
| `apps/api` | API coverage/build, browser, API container |
| `apps/mcp` | MCP coverage/build and MCP container; no browser or desktop |
| `apps/desktop` | Rust checks and macOS/Windows compile; web lane only when web inputs changed |
| `Dockerfile`, `compose.yaml`, deploy config | container build/config/security plus affected app builds |

### P0 — Add Terraform review-quality CI

Retain format and validate, but initialize both roots with
`-lockfile=readonly -input=false -no-color` and set `TF_IN_AUTOMATION=1`. Add:

- TFLint with the recommended Terraform rules and the AWS ruleset, pinned in
  `.tflint.hcl`, run recursively for `infra/` and separately for
  `infra/bootstrap/`.
- Trivy configuration scanning for `infra/`, `Dockerfile`, and `compose.yaml`,
  with a reviewed, minimal ignore file and a high/critical blocking threshold.
- Native `.tftest.hcl` tests with mocked AWS and Cloudflare providers for the
  highest-value invariants: GitHub OIDC subject restriction, production
  deletion protection, private/encrypted database, public-bucket blocking,
  immutable/scanned ECR repositories, and the Plaid/push configuration checks.

Add a second, credentialed speculative-plan job for trusted same-repository PRs
that touch `infra/**`. It must use a dedicated GitHub OIDC role, not the deploy
role, and a read-only Cloudflare token. The AWS role should have only state-read,
state-lock-file, and required `Get`/`List`/`Describe` permissions. Run against
the real S3 backend and production variables with `terraform plan -input=false
-no-color -detailed-exitcode`.

Publish a redacted text plan to the job summary and logs. Never upload or commit
the binary plan or JSON plan: HashiCorp warns that saved plans contain state,
configuration, variable values, and sensitive values in cleartext. Treat exit
code 0 as “no changes,” 2 as “changes proposed,” and 1 as failure. Recreate the
plan after merge before any future automated apply; a PR speculative plan is
never an apply artifact.

### P1 — Remove redundant work and cancel obsolete runs

- Add `concurrency.group: ci-${{ github.event.pull_request.number || github.ref
  }}` and cancel in-progress runs for pull requests, but not `main`.
- Split the current `check` command into composable scripts so CI does not run
  lint twice. Preserve `pnpm verify` as the complete local contract.
- Use Biome's `ci` command in Actions. Restrict it to changed files on PRs only
  after retaining full typechecks for downstream effects; Biome warns that
  changed-file linting does not inspect importers.
- Continue using `setup-node`'s pnpm store cache. Do not cache Playwright browser
  binaries: Playwright says restoration often costs as much as downloading.
  Install Chromium only and evaluate `--only-shell` because the suite uses
  headless bundled Chromium.
- Add a Rust build cache keyed by `Cargo.lock`, runner OS, and pinned Rust
  toolchain. Cache only when the desktop lane runs.
- Build deployable Docker targets in CI with BuildKit cache scopes per image.

### P1 — Make coverage independently enforceable

The current 95% statement/function/line and 94% branch thresholds are global.
That prevents safe package-scoped coverage because skipping unaffected tests
would report untouched source as uncovered, and it can also allow one very
well-tested package to subsidize another.

Introduce Vitest projects aligned to the repository ownership boundaries. Each
project should own its test glob and coverage include glob. Establish per-project
floors at no less than each project's measured baseline, add tests until every
project reaches the repository's existing 95/95/95/94 policy, and only then
switch PRs to affected-project coverage. Always run all projects and the global
coverage report on `main`. pnpm's `...[base]` filtering can select changed
packages plus all transitive dependents; root files and unknown paths must select
all projects.

### P1 — Close platform-specific gaps

- Database: run `drizzle-kit check` and a clean PostgreSQL migration replay when
  schema, migration, Drizzle, or database code changes. Keep the existing API
  integration suite for behavior and data-preservation tests.
- Containers: validate `docker compose config`; build the `api`, `mcp`, and
  `web` targets before deployment on affected changes; scan the built runtime
  images or continue ECR scanning as a second defense.
- Tauri/Rust: on desktop changes run `cargo fmt --check`, `cargo clippy
  --all-targets --all-features -- -D warnings`, and `cargo test` on Linux before
  the conditional macOS/Windows compile matrix. Pin Rust in
  `rust-toolchain.toml` and update it deliberately.
- Workflows: run pinned actionlint with ShellCheck integration when `.github/**`
  or shell files change. Compile-check Python helpers and `node --check` plain
  JavaScript helpers. Pin every third-party action to a full commit SHA, retaining
  the release tag in a comment for Dependabot/readability.
- Dependencies: use GitHub's dependency review action on PRs that change
  manifests/lockfiles and fail on newly introduced high/critical production
  vulnerabilities. Move the full `pnpm audit --prod` to a scheduled security
  workflow and `main`, so existing advisories are still detected without making
  every unrelated PR depend on the registry.
- Code scanning: enable GitHub CodeQL default setup for JavaScript/TypeScript and
  GitHub Actions if available for the repository. Treat this as a repository
  security setting, not part of the required fast PR path.

### P2 — Make deployment proportional and least-privileged

Pass an attested or independently recomputed `deployable` classification from a
successful `main` CI run so documentation-only and agent-skill-only merges do not
build images or deploy production. Fail closed when the comparison base cannot
be established. Keep deployment serialized and never cancel a running
production deployment.

Move `issues: write`, `statuses: write`, and `id-token: write` from workflow
scope to only the jobs that use them. Preserve the production environment and
OIDC deployment role. GitHub specifically warns that `workflow_run` workflows
must not check out untrusted PR content; the existing main-branch restriction is
important and must remain covered by workflow-contract tests.

## Safety and rollout rules

1. The first routing PR runs the old full jobs and the new classifier in shadow
   mode and records mismatches without skipping anything.
2. The second PR enables skips only for docs-only and Terraform-only changes.
3. Subsequent PRs enable application scopes one ownership boundary at a time.
4. For at least two weeks, a scheduled full run compares selective PR outcomes
   with the full suite and opens an issue for any classifier miss.
5. Branch protection requires only the stable `CI required` aggregate check;
   conditional implementation-job names are not required directly.
6. Any classifier error, unknown path, root dependency/toolchain change, or CI
   workflow change runs full CI.
7. `main`, release tags, and manual release/deployment paths retain full or
   release-specific validation.

## Success metrics

Capture these before enabling skips and report p50/p95 weekly:

- pull-request critical-path duration;
- total runner-minutes by OS;
- cancellation rate and runner-minutes avoided;
- cache hit rate;
- percent of PRs by selected scope;
- flaky rerun rate;
- selective/full mismatch count (target: zero);
- Terraform plan availability and plan failure rate;
- deployment failures caused by build/configuration issues (target: zero).

Initial goals after the staged rollout:

- docs-only and Terraform-only PRs finish in under 3 minutes;
- MCP-only PRs do not start Playwright or desktop jobs;
- superseded PR runs cancel within one minute;
- no Docker build first occurs in the production deployment;
- every Terraform PR has static analysis, and trusted Terraform PRs have a
  real-state speculative plan;
- the `main` full gate retains the current coverage thresholds and acceptance
  projects.

## Implementation evidence

The first two implementation stages are present on
`cooper/ci-hardening-and-acceleration` as separate commits. The classifier is
fail-closed, derives transitive dependents from the workspace manifests, and
has executable fixtures for documentation, Terraform, MCP, web, database,
lockfile, and unknown-path changes. Local evidence as of August 26, 2026:

- 28 classifier, CLI, and aggregate-gate tests pass;
- Biome passes for the classifier and repository scripts;
- actionlint accepts the conditional workflow and stable aggregate job;
- the repository lifecycle and classifier check (`pnpm check:repo`) passes;
- the formerly clock-dependent calendar test now passes with a fixed test
  clock and no production behavior change.

A full `pnpm verify` rerun must still be captured in a quiet execution window.
The attempted rerun overlapped multiple unrelated host-wide `verify` and
`verify:pr` processes; unrelated five-second integration and UI tests timed out
across several files, so that run is not valid release evidence. ShellCheck
also reports the pre-existing SC2015 and SC2155 findings in
`.codex/scripts/environment.sh`; this change does not modify that script.

Do not update branch protection from the local result alone. First publish the
shadow classifier, then validate one documentation-only and one Terraform-only
pull request. Record their selected jobs and elapsed times here before making
`CI required` the sole required branch-protection check. Application-specific
skips should follow the staged rollout rules above even though the final routing
conditions are implemented and locally validated on this branch.
