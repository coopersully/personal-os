delegate on your terms.

give an agent context, access, and a clear stopping point.

delegate with a clear boundary

connect your chosen agent through the supported connected-agent setup. read access, write access, and execution authority are different. grant only what the job needs. some changes can be made directly under existing write policy; others require a review, explicit execution authority, or your own action.

  • give context: name the workspace, outcome, relevant records, and constraints.
  • define authority: say whether you want an explanation, a draft, a proposal, or an allowed change.
  • inspect results: look for actual record updates and completed outcomes, not just an agent saying “done.” pending and uncertain results still need attention.
  • keep control: review permissions and revoke access when needed. agents cannot grant themselves access, change their own approval bypass, or complete provider login and phone verification for you.

recurring work: schedules run through a supported external agent host. the host invokes work; nohmi keeps records, permissions, and workflow state. a stored schedule alone does not establish that the host is connected or that a run succeeded.

texting: optional texting is a shared inbox, not another workspace. open settings → texting, read the disclosures, opt in, and verify your number. use supported messages and review flows to stay connected; delivery, consent, and workspace authorization still apply. see texting terms and data and agent access.

when something needs attention

  • stale data: check the source’s last sync and connection health. reconnect through the app if authorization expired.
  • unavailable action: inspect the provider’s capabilities and your permissions. use the provider directly if nohmi does not support that operation.
  • conflicting changes: reload the current record and review the new state before retrying. do not overwrite someone else’s changes from an old preview.
  • uncertain delivery: inspect the recorded outcome and recovery flow. do not blindly repeat a mail send or connection exchange.
  • an unresolved question: open the owning workspace, inspect the evidence, and provide the missing context. uncertainty should stay visible until resolved.

contact support with the workspace, approximate time, and what you expected. never send passwords, verification codes, full account numbers, or private message contents.
